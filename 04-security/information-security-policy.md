# 信息安全政策 (Information Security Policy)

Owner: Lin (Tech Lead) · Status: Draft v0.1 · Last reviewed: 04/10/2026 · 每年复核

## 目标
保护住户健康信息和客户数据的机密性、完整性、可用性；能通过 aged care provider 的供应商安全尽调；路线图对齐 ASD Essential Eight → ISO/IEC 27001。

## 基线控制（第一个客户前必须到位）
| 领域 | 控制 | 状态 |
|---|---|---|
| 身份 | 所有系统 SSO + MFA（管理员用防钓鱼 MFA / 硬件密钥）；无共享账号 | 🔴 |
| 设备 | 公司设备全盘加密、自动锁屏、自动更新、MDM；个人设备不得访问生产数据 | 🔴 |
| 数据驻留 | 生产数据与 LLM 推理均在澳洲区域 | 🔴 |
| 加密 | 传输 TLS 1.2+；静态加密 (KMS)；音频与记录字段级加密（考虑） | 🔴 |
| 租户隔离 | 每个 provider 逻辑隔离；所有查询强制 tenant 过滤；自动化测试覆盖 | 🔴 |
| 访问 | 最小权限；生产访问需审批 + 限时 + 审计日志；季度权限审查 | 🔴 |
| 日志与监控 | 集中日志、告警、访问审计日志保留 ≥ 12 个月 | 🔴 |
| 备份 | 自动备份、加密、境内、每季度恢复演练 | 🔴 |
| 漏洞管理 | 依赖扫描、补丁 SLA（严重 48h / 高 14 天）、上线前第三方渗透测试 | 🔴 |
| 安全开发 | 代码审查、密钥不进代码库（secret scanning）、环境隔离、生产数据不进开发环境 | 🔴 |
| 供应商 | 子处理方安全评估与登记 | 🔴 |
| 人员 | 背景调查（police check）、保密协议、安全培训、离职当天撤权 | 🔴 |
| 事故 | `03-legal-compliance/data-breach-response-plan.md` | 🟡 |
| 业务连续性 | RTO/RPO 目标 {{TBD}}；护士可退回手动记录 | 🔴 |

## Essential Eight 对照（目标 ML1 → ML2）
应用控制 · 修补应用 · 配置 Office 宏 · 用户应用加固 · 限制管理员权限 · 修补操作系统 · 多因素认证 · 定期备份 —— 云原生 SaaS 公司主要适用于员工终端和管理面，逐项记录适用性与证据。
