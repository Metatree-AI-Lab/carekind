# PRD：Shift Capture（整班录音）+ 按老人自动分配记录 + 老人档案

Owner: Lightman (PO) · Tech: Lin (Tech Lead) · Status: **Draft** · Last reviewed: 04/10/2026
Parent: [`docs/PRD.md`](../PRD.md) · Related: `00-company/product-thesis.md` · `03-legal-compliance/tga-samd-boundary.md` · `03-legal-compliance/privacy-program.md` · `06-app-development/clinical-safety/hazard-log.md` · `03-legal-compliance/references/paperwork-taxonomy.md`

> 一句话：护士在班次开始时打开录音，边工作边口述观察；careKind 把整个班次（例如 8 小时）的录音自动拆分成一个个事件，**分配到对应的老人名下**，起草 progress notes、交接、图表等文档。护士审核确认后，记录写入每位老人的**档案时间线**，并导出到机构的临床系统。

---

## 1. 问题

### 1.1 谁、在什么场景、遇到什么问题
- **RN / EN / PCW** 一个班次要照护十几到几十位老人。观察和照护是分散发生的，记录却集中在班末或下班后补写：
  - 细节在几个小时后会遗忘或混淆，记录变得笼统（"resident settled"），可能写到错误的老人名下，事件时间也不准；
  - 一个班次要在临床系统里为每位老人分别打开页面、逐条录入，重复劳动很多；
  - 英语非母语的护理员写英文记录慢，压力也大。
- **护理经理 / DON** 需要每位老人的记录完整、及时、具体，这样才能满足 Strengthened Quality Standards 2.7.2（信息准确完整）、3.3（关键信息沟通与交接）、5.4.5（监测临床状况），并经得起 ACQSC 审计。

### 1.2 证据（诚实标注）
| 证据 | 来源 | 强度 |
|---|---|---|
| 护士访谈 | 尚无（`10-feedback/` 为空） | **n = 0，以下都是假设** |
| Progress notes、交接是 AI 适合度最高、TGA 风险最低的文书 | `03-legal-compliance/references/paperwork-taxonomy.md` §1、§7.12 | 中（基于法规与模板分析） |
| 竞品已在养老场景做 ambient 录音（Heidi，新西兰 Metlifecare 4 家护理院，RN 审核） | `01-strategy/competitive-research/ai-features-comparison.md`（S46） | 中（公开报道，未试用） |
| 竞品普遍是"单次口述 → 单条记录"，公开资料里没有"整班录音 → 自动按老人分配"的产品 | 同上 | 弱到中（可能只是没公开，需要试用确认） |

**必须先验证的假设**
- **H1**：护士愿意在整个班次随身录音，并以口述的方式边做边记。
- **H2**：自动分配到老人的准确率能做到让护士信任，"审核比自己写更快"。
- **H3**：机构（以及员工、老人、家属）能接受整班录音的隐私安排。
- **H4**：按老人汇总的档案时间线对交接和护理经理有独立价值。

## 2. 目标与指标

### 2.1 目标
1. 把护士每班次花在文书上的时间显著减少，同时不降低记录质量。
2. 记录更及时（贴近事件发生时间）、更具体，每条都归到正确的老人名下。
3. 给每位老人一份可追溯的情况时间线，支持交接和照护连续性。

| 指标 | 定义 | 目标 |
|---|---|---|

## 4. 方案

### 4.1 核心概念
| 概念 | 说明 |
|---|---|
| **Shift Session（班次会话）** | 一个护士的一个班次，包括录音、事件、草稿和确认状态 |
| **Segment（片段）** | 由语音活动检测切出来的一段语音 |
| **Event（事件）** | 关于**一位**老人的一次观察或照护叙述，可能由一个或多个片段组成 |
| **Attribution（归属）** | 事件 → 老人的匹配结果和置信度 |
| **Draft（草稿）** | 由事件生成、按文书类型整理的记录草稿 |
| **Resident Profile（老人档案）** | 老人的基础信息加上已确认记录的时间线 |

### 4.2 两种录音模式
| | **模式 A：口述整班录音（MVP）** | **模式 B：环境对话录音（Phase 3，有法律门槛）** |
|---|---|---|
| 录什么 | 护士本人的口述，例如"12 号房 Mrs Smith，早餐吃了一半，说膝盖疼……" | 护士与老人之间的照护对话 |
| 怎么处理别人的声音 | 用**护士声纹注册**和说话人分离：**设备端只保留护士本人的语音**，其他人的语音不上传、即时丢弃 | 保留对话双方，只对已登记同意的老人生效 |
| 法律风险 | 中（仍需律师确认，见 §6） | **高**：涉及监控设备法、老人的同意能力、在老人家中（房间）录音 |
| 上线条件 | 律师意见 + 机构政策 + 员工告知 | 律师意见 + 同意登记系统 + 替代决策人流程 + ADR + 机构董事会批准 |

### 4.3 主流程（模式 A）

**① 班次开始**
- 护士登录 → 选择单元或区域 → 加载本班老人名单（来自临床系统或手动维护）。
- 名单里每位老人有：姓名、偏好称呼、房间号、照片（用于确认）、语言、同意状态。
- 点击 **"开始班次录音"**。屏幕上持续显示录音状态，可以一键暂停或继续。
- 设备端开始：语音活动检测（只在有人说话时录）+ 声纹过滤（只保留护士本人）。

**② 班次进行中**
- 护士照常工作，想记的时候直接说。**推荐的口述习惯**（培训内容）：先说房间号或名字，再说观察。系统也能处理不规范的说法。
- 可选的**快捷标记**：长按耳机键或 App 按钮表示"新的一位老人"，帮助切分。
- 敏感时刻（如为老人洗澡、如厕）可以一键暂停，或者设置自动暂停区域（Phase 2）。
- 音频分块加密，在澳洲境内上传；**网络不好时先在设备端加密缓存**，恢复后续传。
- 后台近实时处理：每段口述在几分钟内变成草稿，护士可以在空档随时查看。

**③ 处理流水线（后端，澳洲区域）**
1. **转写（ASR）**：支持口音，使用自定义词表（本单元老人姓名、昵称、常用药名、机构术语）；每个词带置信度。
2. **切分成事件**：结合停顿、快捷标记和语义话题变化，把连续录音切成"每次只关于一位老人"的事件。一段话提到多位老人时，拆成多个事件。
3. **老人归属**：对照本班名单做实体匹配（全名、姓氏、偏好称呼、房间号、"她隔壁那位"之类的上下文），输出候选老人和置信度。
   - 置信度 ≥ 阈值且只有唯一候选 → 自动分配
   - 低于阈值、出现同名或近似名、或者没有提到任何人 → 放进 **"待分配"**队列，**不猜**
   - **永远不分配给本班名单以外的老人**
4. **事件时间**：用录音时间戳作为"记录时间"；口述中明确说出的时间（"大概 3 点的时候"）作为"事件时间"，两者都保留。
5. **文书分类**：progress note、交接要点、behaviour chart 条目、food & fluid 条目、家属沟通记录、疑似事件（转 incident 草稿，Phase 2）。
6. **起草**：只整理护士说过的内容，按机构模板生成；客观、person-centred；**不加入任何没说过的事实**。
7. **事实一致性检查**：比对草稿和转写原文，标出新增或改动的内容；数值（体温、血糖、摄入量、药名、剂量）必须和原文完全一致，低置信度的要求人工确认。

**④ 审核（核心界面）**
- **按老人分组的审核收件箱**：每位老人一张卡片，显示待审核草稿数量。
- 每条草稿**并排显示**：草稿 ↔ 转写原文（可以点开回放这段音频）；AI 改写的部分高亮；低置信度的词加下划线。
- 归属显示为"Mrs Smith · 12 号房 · 照片"，可以一键改成另一位老人。
- 操作：确认 / 编辑后确认 / 改归属 / 拆分 / 合并 / 删除（例如误录）。
- **"待分配"队列**必须清空，班次才能结束。
- **批量确认**：只对高置信度、非敏感、没有数值字段的常规记录开放，而且每条仍会展开显示。**敏感事件**（跌倒、伤害、行为、限制性措施、疑似虐待、病情变化、临终）**必须逐条单独确认**。
- 确认后：记录写入老人档案，并进入导出或集成队列。

**⑤ 班次结束**
- 显示**本班覆盖情况**：哪些老人有记录、哪些还没有（只提示，不自动补写）。
- 一键生成**交接摘要**（ISBAR）：S 和 B 来自已确认的记录；**A 和 R 栏只用护士的原话，没有说过就显示"请填写"**。
- 结束录音会话，按保留策略处理音频（§7）。

### 4.4 老人档案（Resident Profile）
| 模块 | 内容 | 规则 |
|---|---|---|
| 基础信息 | 姓名、偏好称呼、房间号、照片、语言与沟通需求、文化与宗教偏好、重要联系人 | 来自临床系统或管理员录入；careKind 不是主数据源 |
| "了解我"笔记 | 喜好、习惯、能让老人安心的方式等 person-centred 信息 | 由员工确认后录入 |
| **记录时间线** | 所有已确认记录，按时间排序，可按类型筛选（progress、behaviour、food & fluid、家属沟通……） | 每条显示作者、审核人、时间，可追溯到原始转写 |
| **近期情况汇总** | 例如"过去 7 天的已确认记录要点" | **只复述已确认记录，每句附来源链接**；不做趋势判断、风险评分或异常告警（TGA，见 §5） |
| 导出 | 按老人、按时间范围导出（PDF / 结构化格式） | 支持老人和家属的访问请求（APP 12）、审计、转院 |

> ⚠️ **待决策（ADR）**：careKind 是**过渡层**（记录确认后导出到临床系统，careKind 只短期保留），还是**记录系统**（长期保存每位老人的档案）？如果是后者，我们就要承担州健康记录法的保存义务（VIC 成人健康记录至少 7 年）、访问和更正请求，安全与合同要求也会更高。**MVP 建议做过渡层**：档案时间线保留期跟合同走，以临床系统为准。

### 4.5 范围
| ✅ MVP（试点） | ⏭ Phase 2 | ⏭ Phase 3（有门槛） | ❌ 不做 |
|---|---|---|---|
| 模式 A 整班口述录音 + 声纹过滤 | Incident report 草稿 + SIRS 流程提示（只提示，不判定） | 模式 B 环境对话录音 | 诊断、风险评分、恶化预测 |
| 事件切分 + 老人归属 + 待分配队列 | Behaviour chart（ABC）、food & fluid 条目 | 临床系统深度双向集成（多家） | 治疗或用药建议 |
| Progress notes 草稿 + 审核收件箱 | 多语言口述 → 英文（3–5 种语言） | 自动暂停区域（如浴室） | 根据数值自动报警 |
| 班末交接摘要（ISBAR） | 首个临床系统集成 | | 自动写入，没有人工确认 |
| 老人档案：基础信息 + 时间线 + 导出 | 家属沟通记录 | | 用录音评价或监控员工绩效 |
| 本班覆盖情况提示 | 护理经理视图（单元总览） | | AN-ACC "优化"写作建议 |
| 管理后台：名单、模式、保留期、同意状态 | | | |

## 5. TGA boundary check ✅

**结论：🟡（MVP 整体为 🟢，有两个功能需要守住边界）。** 运营参考，不是法规意见；🟡 部分需要法规顾问确认。

| 功能 | 判定 | 理由 |
|---|---|---|
| 转写、切分、按老人归属、按模板起草 | 🟢 | 只整理员工自己说的内容。TGA digital scribes 页面（2026-01-30 更新）明确把"transcribe… into written records without performing analysis or interpretation"排除在医疗器械之外 |
| 交接摘要 | 🟢 / 🟡 | S、B 复述已确认记录是 🟢；A 和 R 栏如果让 AI 自己写，就变成"生成没有说过的评估或建议" → **只用原话，否则留空** |
| 老人档案"近期情况汇总" | 🟡 | 复述已确认记录是 🟢；一旦出现"趋势""恶化""风险上升"之类的分析解读就可能构成 SaMD → **禁止趋势判断和告警，每句必须附来源** |
| 本班覆盖情况提示（哪些老人没有记录） | 🟢 | 文书流程提示，不涉及临床判断 |
| 敏感事件识别（用于强制逐条确认） | 🟢 / 🟡 | 用于审核流程（"这条需要单独确认"）是 🟢；对外表述成"检测跌倒风险或虐待"就是 🔴 → 文案只能说"标记需要单独审核的记录" |

**禁用文案**：detect、predict、monitor condition、early warning、risk score、clinical insights。
**可用文案**："helps you document your shift"、"sorts your notes by resident"、"you review and approve every note"。

## 6. 法律与隐私影响 ✅（本 PRD 最大的风险）

> ⚠️ 运营参考，不是法律意见。**模式 A 上线前必须拿到书面律师意见。**

| 议题 | 风险 | 设计应对 | 状态 |
|---|---|---|---|
| **监控设备法**：Surveillance Devices Act 1999 (Vic)、Surveillance Devices Act 2007 (NSW) 等，各州不同 | 整班录音可能录到护士**不在场**的私人谈话（老人、家属、其他员工之间）。VIC 一般允许谈话参与方录音，但禁止录制自己不在场的私人谈话；NSW 对参与方录音也更严格 | 模式 A：**设备端声纹过滤，只保留护士本人的语音**，其他声音不上传、不存储；可见的录音状态指示；一键暂停；按州配置 | ⚠️ 需律师按州确认 |
| **工作场所监控** | NSW Workplace Surveillance Act 2005 要求提前书面通知员工；ACT 有 Workplace Privacy Act 2011；VIC 没有专门的法律，但涉及 OHS 和劳资关系 | 员工告知与同意流程；**合同和产品承诺录音不用于绩效监控**；建议与员工代表协商 | ⚠️ 需律师确认 |
| **老人的权利与同意**（Aged Care Act 2024 的 Statement of Rights；房间就是老人的家） | 认知障碍老人的同意能力；隐私与尊严 | 模式 A 只保留护士的声音；老人和家属告知（`09-templates/resident-ai-notice.md`）；老人可以选择退出 → 护士在其房间内自动或手动暂停；名单显示同意状态 | 🔴 待设计 |
| **APP 3 收集必要性** | 整班录音容易"收集过多" | 语音活动检测 + 声纹过滤 + 无关内容不进入结构化存储 + 音频短期保留 | 🟡 |
| **APP 11 安全** | 音频是 Restricted 数据；设备丢失 | 设备端加密缓存、远程擦除、境内处理、最小权限（`04-security/`） | 🟡 |
| **APP 1.7–1.9 自动化决策透明度（2026-12-10 生效）** | 自动归属和分类是否算"自动化决策"？ | 归属最终由护士确认，不是决定；但隐私政策仍要披露 AI 处理方式 | ⚠️ 需律师确认 |
| **记录系统定性** | 长期保存档案 → 州健康记录法的保存与访问义务 | MVP 做过渡层（§4.4 ADR） | 🔴 待 ADR |
| **子处理方** | 声纹、ASR、LLM 都处理 Restricted 数据 | 全部在澳洲区域，零数据保留（ADR-0001）；更新子处理方登记 | 🔴 |

**需要更新的文档**：PIA（新增：声纹生物特征数据、整班音频）· 隐私政策（AI 处理与自动归属披露）· DPA（音频保留、声纹）· 住户告知模板（加入录音说明）· 员工告知模板（新建）。

> ⚠️ **声纹属于生物特征信息，在 Privacy Act 下是 sensitive information。**需要护士的明示同意；只用于本人语音过滤，不用于身份识别或考勤，离职后删除。

## 11. 上线计划与回滚

1. **Alpha（内部）**：用合成整班录音跑评测，达到门槛。
2. **法律门槛**：拿到监控设备法、工作场所监控、声纹同意的书面律师意见（VIC 优先）→ 🧑 Lightman 批准。
3. **试点（1 家机构、1 个单元、8–12 周，VIC）**：
   - 试点前：基线时间研究；员工告知与同意；老人和家属告知；培训（口述习惯、审核要求）。
   - 第 1–2 周：只启用 progress notes，每天抽样审核归属准确率。
   - 第 3 周起：加入交接摘要。
4. **回滚**：任何一次错配进入正式记录 → 暂停自动分配（切到"全部人工分配"模式）→ 走事故流程（`11-workflows/incident-response.md`）。
