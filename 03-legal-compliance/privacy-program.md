# 隐私方案 (Privacy Program)

Owner: Privacy Officer（暂由 Lightman 兼任）· Status: Draft · Last reviewed: 04/10/2026

> 我们处理的是**老人的健康信息**——Privacy Act 下最敏感的一类。把隐私当成产品特性来卖，而不是负担。

## 1. 我们处理哪些个人信息
| 数据类别 | 例子 | 敏感级 | 来源 |
|---|---|---|---|
| 住户健康信息 | 口述内容、记录草稿、事件细节、健康状况 | **Sensitive / Restricted** | 护士输入 |
| 住户身份信息 | 姓名、房号、出生日期、ID | Restricted | Provider 系统 |
| 语音录音 | 护士口述音频 | **Restricted**（含健康信息+声纹） | App |
| 员工用户信息 | 护士姓名、邮箱、角色、AHPRA 号、使用日志 | Confidential | Provider |
| 买方联系人 | 姓名、职位、邮箱 | Internal | 销售 |
| 网站访客 | Cookie、分析数据 | Internal | 官网 |

## 2. 我们的角色
- 对住户数据：我们**代表 provider 处理**（类似 processor / contracted service provider）。Provider 是与住户关系的主要责任方，但**澳洲隐私法没有 GDPR 式的 controller/processor 豁免**——我们自己也直接受 APPs 约束。⚠️ 需律师确认
- 对员工用户、买方联系人、网站访客：我们是收集方。

## 3. APPs 落地对照
| APP | 要求 | 我们怎么做 |
|---|---|---|
| 1 公开透明管理 | 隐私政策、内部治理 | 官网隐私政策（含 AI/自动化决策披露）；本方案；年度复核 |
| 2 匿名/化名 | 可行时允许 | 网站咨询允许化名；产品内住户可用内部 ID |
| 3 收集 | 必要性；敏感信息需同意或例外 | 只收集生成记录所需信息；provider 负责获取住户/代表的同意并告知 AI 使用（合同约定 + 提供告知模板） |
| 4 未经请求的信息 | 不需要就销毁 | 口述中的无关信息不进入结构化存储 |
| 5 收集通知 | 告知收集事项 | 给 provider 的住户告知模板；App 内护士告知 |
| 6 使用与披露 | 仅用于主要目的 | **不用客户数据训练通用模型**（除非单独书面同意 + 去标识化）；不卖数据 |
| 7 直接营销 | 限制 | 住户数据绝不用于营销 |
| 8 跨境披露 | 对境外接收方负责 | 默认澳洲境内处理与存储（含 LLM 推理）；子处理方登记 |
| 9 政府标识符 | 不采用作自己的标识 | 不用 Medicare 号等作主键 |
| 10 质量 | 准确、最新 | 护士审核流程；可更正 |
| 11 安全 | 合理措施保护；不再需要时销毁/去标识化 | `04-security/`；音频默认短期保留后删除 |
| 12 访问 | 个人可请求访问 | 通过 provider 渠道响应；30 天内 |
| 13 更正 | 个人可请求更正 | 同上 |

## 4. 关键设计决定
1. **音频保留**：音频转写完成并护士确认后 {{TBD: 例如 7 天}} 内删除；正式记录保存在 provider 系统中 → ADR
2. **数据驻留**：全部在澳洲区域（如 AWS ap-southeast-2 / ap-southeast-4 或 Azure Australia East），LLM 通过境内端点调用，零数据保留 (zero data retention) 配置 → ADR-0001
3. **模型训练**：默认不用客户数据训练。任何改进用数据需：provider 书面同意 + 去标识化 + 隐私影响评估
4. **最小权限**：员工默认看不到客户数据；支持工单访问需客户授权并留审计日志

## 5. 隐私影响评估 (PIA)
